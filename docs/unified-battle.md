# One battle system
The former layered skirmish scene is a compatibility launcher for BattleScene. Normal BattleScene accepts a GameState with an authored floor graph; it uses BoardView, BattleHud, BattleInput, EventPlayer, BotRunner, graphics settings and the usual checkpoint pipeline. Floor selection is a view/filter operation. BattleMovementOptions provides the same route/cost/commit contract for exposed heightfields and explicit floor graphs, retaining surface identity. GameController owns movement spending and post-move effects; RunForIt owns run completion. Layered site crossings retain the actual position and surface, and movement animation precedes the null-field event. Bot owns activation selection, cast resolution and completion on both geometries, using the common MagicBot for supported figure spells. Geometry-specific route tactics are still separate. The old floor-specific controls are no longer part of the running game. Stacked solids also consume the same architectural relief helper as ordinary ruins, and BoardView owns their cutaway presentation.

This is a migration milestone, not full geometry parity. Existing single-surface scenario layouts and saves are preserved. The underlying flat MoveGrid and explicit LayeredGrid are still different geometry providers. Layered movement still has conservative restrictions on reactions, certain terrain spells and scenario hooks; not all magic/gear/AI has been migrated. Do not replace the production Silent Tower or enable arbitrary campaign layered maps until these restrictions are removed and scenario tests pass. Next: common floor-aware reach/sight/occupancy queries and common movement effect/reaction pipeline, then all spell/gear placement, bot tactics and scenario migration. Keep gameplay tests parameterized across flat/uneven/overlapping floors. Never implement parallel player UI or scene flows again.

Movement contact/occupancy and guard eligibility now share a rule policy. Floor-route interception uses actual surface and height, supports the normal reaction prompt, and extraction waits for the committed route rather than securing loot on declaration. Beauty authorization and illusion contact are shared with ordinary movement.

Figure spell selection now uses one SpellAvailability menu on both geometries. Status spells, control, time effects, supported area spells, weapon decay, figure dispelling and ordinary non-placement potions are no longer disabled just because a board has stacked floors. Counter magic can target a visible conjured floor bridge. Relocation and terrain spell exceptions remain explicitly guarded until their full placement/effect paths are migrated.

All ordinary movement reach, AI distance/exit fields, and explicit floor routes now use RouteSearch's common priority-queue solver. Geometry-specific edge costs remain typed to avoid mobile allocation overhead. Board caches its read-only floor geometry by authored-layout revision (including bridge changes). Floor-targeted magic and shooting use one physical floor ray with boundary and darkness checks. Teleport/Leap also run normal arrival and illusion hooks.

Summoning, teleport spells, ring teleportation and teleport potions now use explicit floor placement and shared legality/arrival helpers. Summons share the existing limits, gear bonuses, allegiance and miscast rules; MagicBot can choose floor summons. UI routes them through the same spellbook/items and floor destination markers.

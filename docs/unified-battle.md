# One battle system
The former layered skirmish scene is a compatibility launcher for BattleScene. Normal BattleScene accepts a GameState with an authored floor graph; it uses BoardView, BattleHud, BattleInput, EventPlayer, BotRunner, graphics settings and the usual checkpoint pipeline. Floor selection is a view/filter operation. BattleMovementOptions provides the same route/cost/commit contract for exposed heightfields and explicit floor graphs, retaining surface identity. GameController owns movement spending and post-move effects; RunForIt owns run completion. Layered site crossings retain the actual position and surface, and movement animation precedes the null-field event. Bot owns activation selection, cast resolution and completion on both geometries, using the common MagicBot for supported figure spells. Geometry-specific route tactics are still separate. The old floor-specific controls are no longer part of the running game.

This is a migration milestone, not full geometry parity. Existing single-surface scenario layouts and saves are preserved. The underlying flat MoveGrid and explicit LayeredGrid are still different geometry providers. Layered movement still has conservative restrictions on reactions, certain terrain spells and scenario hooks; not all magic/gear/AI has been migrated. Do not replace the production Silent Tower or enable arbitrary campaign layered maps until these restrictions are removed and scenario tests pass. Next: common floor-aware reach/sight/occupancy queries and common movement effect/reaction pipeline, then all spell/gear placement, bot tactics and scenario migration. Keep gameplay tests parameterized across flat/uneven/overlapping floors. Never implement parallel player UI or scene flows again.
